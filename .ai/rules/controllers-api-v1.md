# Controllers Api V1

## Stocks : catalogue d'organisation, écritures bornées à la clinique du jeton
Produits = NIVEAU ORGANISATION (fiche partagée) ; quantités dans `stocks` (pivot produit × clinique), commandes fournisseur et lots = clinique. LECTURE transversale : la ventilation des stocks et le journal des mouvements se lisent toutes cliniques de l'organisation (withoutGlobalScope('clinique') borné par le produit scopé organisation) ; ÉCRITURES uniquement via GestionnaireStock, clinique du jeton, jamais d'update direct de `stocks` : chaque geste laisse une ligne immuable dans `mouvements_stock` (écart réel, borné à zéro), un undo est un mouvement inverse (inverserMouvementsDe). Le seuil d'alerte et les commandes auto s'évaluent sur le stock TOTAL de l'organisation (parité front). Numérotation des pièces (FC/DV/RX/Z/BC) : uniquement via Numeroteur (séquence annuelle par organisation, sous verrou), jamais de compteur ad hoc.

## Facturation : la facture suit le patient, la caisse reste locale, RDV fini = facture
Factures, devis et ordonnances = NIVEAU ORGANISATION (ils suivent le patient) avec `clinique_id` d'émission/d'acte conservé ; clôtures de caisse (Z) = CLINIQUE (tiroir physique). Les gestes de caisse (lignes, encaissement, payer-plus-tard, clôture) exigent clinique du jeton == clinique d'émission (trait GesteDeCaisse) — la lecture, elle, est org-wide. Le passage d'un RDV en `fini` crée la facture de l'acte dérivé du type via CreationFacture::depuisRendezVous (une par RDV, jamais un tampon, débrayable par `sans_facture`) ; c'est un effet système : il a lieu même sans le domaine facturation, mais la réponse ne l'expose qu'avec le Gate. Sortie de stock des lignes med UNE fois (drapeau stock_sorti — payer plus tard sort quand même). Suppressions tolérées : fenêtre de 20 s d'une création (facture non payée/clôturée/assurée, ordonnance active — stock restauré par mouvements inverses), brouillon de devis. Catalogue `prestations` unique par organisation (PrestationsParDefaut, prix ACTES pour les doublons ACTES/FC_CATALOG) ; les 8 actes liés à un type de RDV portent le code du type. `expire` d'un devis est dérivé, jamais stocké. Ordonnances = domaine patients (une ASV les voit, pas la facturation).
